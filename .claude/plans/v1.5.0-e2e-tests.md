# v1.5.0 — E2E Regression Tests (Playwright)

## Goal

Add a comprehensive Playwright E2E test suite covering the 7 most critical user flows. Tests mock the API at the network level (Playwright route interception) so they run against the Next.js frontend standalone — no Docker, PostgreSQL, or backend API needed.

## Approach

- **API mocking via `page.route()`** — intercept all `**/api/**` calls and return deterministic fixture data. This keeps tests fast, deterministic, and runnable without the full stack.
- **Demo login (`loginAsRole`)** — use the existing dev-mode quick-login buttons on the login page.
- **28/28 pages must still build** — Playwright is a dev dependency, not a build-time concern.

## Files to Create

### 1. `playwright.config.ts` (root or `apps/web`)

- Base URL: `http://localhost:3000`
- Test dir: `e2e/`
- Web server: `pnpm --filter @sentience/web dev` on port 3000
- Browsers: Chromium only (fast, sufficient for regression)
- CI-ready: `retries: 2` on CI, `workers: 4`

### 2. `apps/web/e2e/fixtures/api-mocks.ts`

Shared fixture factory that sets up route interception for all API domains:

- `mockAuthRoutes(page)` — `POST /api/auth/login` returns JWT, `GET /api/users/me` returns user
- `mockDeviceRoutes(page)` — `GET /api/devices`, `GET /api/devices/:id`
- `mockAlertRoutes(page)` — `GET /api/alerts`, `PATCH /api/alerts/:id`
- `mockEventRoutes(page)` — `GET /api/events`
- `mockNotificationRoutes(page)` — `GET /api/notifications`, `POST /api/notifications/:id/read`
- `mockApiKeyRoutes(page)` — `GET /api/api-keys`, `POST /api/api-keys`, `PATCH /api/api-keys/:id`, `DELETE /api/api-keys/:id`
- `mockNotificationRuleRoutes(page)` — `GET /api/notification-rules`, `PATCH /api/notification-rules/:id`
- `mockReportRoutes(page)` — `GET /api/reports/summary`, `GET /api/reports/trends`, `POST /api/reports/generate`
- `mockAuditLogRoutes(page)` — `GET /api/audit-logs`, `GET /api/audit-logs/:id`
- `mockHealthRoute(page)` — `GET /api/health`
- `mockAllRoutes(page)` — Composes all of the above.

Each fixture returns deterministic, semantically correct mock data (seeded, not Faker).

### 3. `apps/web/e2e/auth.spec.ts`

**Login flows**
- Login page renders quick-login buttons for all 4 roles
- Clicking admin quick-login redirects to `/dashboard`
- After login, header shows the user's name and role badge
- Sign out clears auth state and redirects to login
- Visit `/dashboard` when unauthenticated redirects to `/login`

### 4. `apps/web/e2e/rbac.spec.ts`

**Navigation filtering**
- Admin sees all 13 sidebar nav items
- Support sees 10 items (not Users, Roles, or Settings)
- Customer sees 5 items (Dashboard, Devices, Alerts, Events, Reports)

**Route guards**
- Admin can visit `/users` → renders user list
- Customer visits `/users` → Access Denied / redirect
- Admin can visit `/admin` → renders admin hub
- Support visits `/admin` → Access Denied

**Customer data isolation**
- Customer logs in → dashboard/device/alerts page only shows that customer's data

### 5. `apps/web/e2e/notifications.spec.ts`

**Notifications page (real API-backed)**
- Loads and displays paginated notifications list
- Shows notification category/severity/status badges correctly
- "Mark as read" calls the API and updates visual state
- "Mark All Read" works on filtered views
- Empty state when no notifications match filter
- Loading skeleton shows then resolves to content

**Bell badge in header**
- Badge shows unread count from API response
- Opening notification dropdown shows latest items

### 6. `apps/web/e2e/api-keys.spec.ts`

**API keys page**
- Loads and displays API key list with masked keys
- Search input filters the displayed list
- Status filter toggles between active/revoked
- Create button opens dialog, fill form, submit → API called → new key appears
- Revoke action changes key status in-place
- Delete action removes key from list
- Copy-to-clipboard button copies the full key

### 7. `apps/web/e2e/notification-rules.spec.ts`

**Notification rules page**
- Loads and displays all rules with current settings
- Toggle a channel (email/web/push) → PATCH API called
- Toggle a role checkbox → PATCH API called
- Threshold slider changes → debounced PATCH API called
- Empty state when no rules exist
- Loading state shows skeleton

### 8. `apps/web/e2e/reports.spec.ts`

**Reports page**
- Loads summary cards and charts
- Date range filter changes the displayed data
- Estate/site/device cascade filters narrow results
- CSV Export button triggers download
- PDF Export button triggers PDF generation (test downloads)
- Loading skeleton shows during fetch
- Error state shows retry button

### 9. `apps/web/e2e/audit-log.spec.ts`

**Audit log page**
- Loads and displays paginated audit log entries
- Action filter shows/hides entries correctly
- Search text filters entries
- Pagination works (Next/Previous)
- CSV Export downloads filtered results
- Loading skeleton shows during fetch
- Empty state when no entries match
- Detail drawer opens on row click

```json
"test:e2e": "playwright test",
"test:e2e:ui": "playwright test --ui",

```

Also add a root-level convenience script in root `package.json`:
```json
"test:e2e": "pnpm --filter @sentience/web test:e2e"
```
