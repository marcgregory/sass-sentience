# Backend API — Sentience IoT Platform

> **v1.0 RC1** — Fastify + PostgreSQL + Drizzle ORM backend foundation.
> Last updated: 2026-07-03

---

## Overview

The Sentience backend API provides RESTful endpoints for all platform resources. It lives in `apps/api/` within the monorepo and uses:

| Layer | Technology |
|-------|-----------|
| HTTP Framework | **Fastify 5** |
| Database | **PostgreSQL 16** (via Docker) |
| ORM | **Drizzle ORM** (with Zod-compatible schemas) |
| Auth | **JWT** (`@fastify/jwt`, 24h token expiry) |
| Validation | **Zod** for request bodies |
| Dev Runner | **tsx** (TypeScript execution, no build step for dev) |

The API runs on port **3001** by default.

---

## Quick Start

```bash
# 1. Start PostgreSQL
pnpm db:start

# 2. Run migrations
pnpm db:migrate

# 3. Seed demo data
pnpm db:seed

# 4. Start the API dev server
pnpm api:dev
```

The API should now be running at `http://localhost:3001`.

## Database

### Docker PostgreSQL

The database runs in a Docker container defined in `apps/api/docker-compose.yml`:

| Property | Value |
|----------|-------|
| Image | `postgres:16-alpine` |
| Port | `5433:5432` (uses 5433 to avoid conflicts with local PostgreSQL) |
| User | `sentience` |
| Password | `sentience` |
| Database | `sentience` |
| Volume | `sentience-pgdata` (persistent storage) |

### Schema

13 tables, matching the `@sentience/types` package:

| Table | Description |
|-------|-------------|
| `users` | Platform user accounts with role FK |
| `roles` | Role definitions (admin, support, installer, customer) |
| `role_permissions` | Resource × action permission matrix |
| `customers` | Tenant/customer organizations |
| `estates` | Physical estates (e.g. Riverside Complex) |
| `sites` | Sites within estates (e.g. Building A) |
| `devices` | IoT devices with telemetry and firmware |
| `events` | Event log with severity/category filtering |
| `alerts` | Alert lifecycle (open → acknowledged → resolved) |
| `audit_logs` | User action audit trail |
| `reports` | Generated report metadata |
| `api_keys` | API key management |
| `settings` | Key-value platform configuration |

### Migrations

Generated by Drizzle Kit:

```bash
# Generate migration after schema changes
pnpm db:generate

# Apply pending migrations
pnpm db:migrate

# Open Drizzle Studio (GUI browser for the database)
pnpm db:studio
```

## API Endpoints

All endpoints are prefixed with `/api`. Protected endpoints require a `Bearer` token in the `Authorization` header.

### Health

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| GET | `/api/health` | No | Server status + DB health check |

```json
{
  "status": "ok",
  "uptime": 123.45,
  "timestamp": "2026-07-03T12:00:00.000Z",
  "db": {
    "status": "healthy",
    "latency": "2ms"
  }
}
```

### Auth

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| POST | `/api/auth/login` | No | Authenticate user, returns JWT |
| GET | `/api/auth/me` | Bearer | Get current user profile |

**Login request:**
```json
{ "email": "admin@sentience.io", "password": "admin123" }
```

**Login response:**
```json
{
  "token": "eyJhbGciOi...",
  "user": { "id": "...", "email": "admin@sentience.io", "name": "Alex Turner", "role": "..." }
}
```

## Query Parameters

List endpoints support common query parameters:

| Parameter | Type | Description |
|-----------|------|-------------|
| `page` | number | Page number (default: 1) |
| `limit` | number | Items per page (default: 20, max: 100) |
| `sort` | string | Field to sort by |
| `order` | `asc` \| `desc` | Sort direction |
| `search` | string | Text search (applies to name/title/description) |
| `status` | string | Filter by status |
| `severity` | string | Filter by severity |

## Architecture Notes

- **Authentication**: JWT tokens with 24h expiry. Pass as `Authorization: Bearer <token>`.
- **Error format**: All errors return `{ message, code, details? }`.
- **Pagination**: List endpoints return `{ data: [], pagination: { page, limit, total, totalPages } }`.
- **Passwords**: Hashed with SHA-256 (development only — use bcrypt/argon2 in production).
- **Separation of concerns**: The API does NOT handle real-time WebSocket events — the existing `apps/realtime` bridge manages Socket.IO connections for live updates.
- **Frontend not yet connected**: The Next.js frontend still uses mock data. Connecting pages to the API is a future sprint.
