# v1.7.0 — Fleet Management: Device Tags & Groups

**Status:** Proposed
**Target release:** v1.7.0
**Theme:** Give operators the ability to organize devices into meaningful collections.

---

## Why This Sprint

The handoff from v1.6.0 identified fleet management as the next highest-value capability. Currently, operators see a flat list of devices with no way to organize or filter them beyond basic status and text search.

Tags and Groups let operators:
- Mark devices by function ("front-door", "boiler-room", "HVAC-zone-3")
- Create groups for shared-action sets ("Building A all sensors", "Critical infrastructure")
- Filter the device list by tag instead of scrolling
- Establish the organizational primitive that future features (bulk ops, notification routing, fleet exports) build on

**Constraint:** Deliberately small sprint. No bulk operations, no batch diagnostics, no fleet exports, no notification routing, no standalone tags management UI.

---

## Scope

### Part 1 — Tags (enhance existing)

The `devices` table already has a `tags` JSONB column and the `Device` type already carries `tags: string[]`. Tags exist in the data model but have **no UI** — operators can't see, add, or filter by them.

- **Devices list:** Show tags as small badges in the device table. Add tag filter chips.
- **Device detail:** Inline tag editor — add/remove free-form tags, persisted via `PATCH /api/devices/:id`.
- **API:** Add `?tags=` filter to `GET /api/devices` (comma-separated, OR logic within tags, AND with other filters).

### Part 2 — Device Groups (new entity)

A Group is a named collection of devices with an explicit (not filter-based) membership list.

- **DB:** New `device_groups` table — `id`, `name`, `description`, `device_ids` (UUID array), `created_at`, `updated_at`.
- **API:** Full CRUD at `/api/device-groups` — list (with search + device count), create, detail (with device list), update, delete. RBAC: admin/support for mutations.
- **Page: Group list** at `/groups` — cards/grid showing name, description, device count, created date. Create/delete dialogs.
- **Page: Group detail** at `/groups/[id]` — Group metadata + scoped device table (reuse existing device table pattern). Edit group name/description. Add/remove devices via searchable multi-select.
- **Loading/Error/Empty:** Every data-driven view gets all three states.

## Implementation Plan

### 1. Types — `@sentience/types`

**New file:** `packages/types/src/device-group.ts`

```ts
export interface DeviceGroup {
  id: string;
  name: string;
  description: string | null;
  deviceIds: string[];
  deviceCount: number;
  createdAt: string;
  updatedAt: string;
}
```

**Modified:** `packages/types/src/index.ts` — export new type.

### 2. Database — `apps/api`

**New migration:** `0007_add_device_groups`

```sql
CREATE TABLE device_groups (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  name TEXT NOT NULL,
  description TEXT,
  device_ids UUID[] NOT NULL DEFAULT '{}',
  device_count INTEGER NOT NULL DEFAULT 0,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX device_groups_name_idx ON device_groups (name);
```

**New file:** `apps/api/src/db/schema/device-groups.ts` — Drizzle schema for the table.

**Modified:** `apps/api/src/db/schema/index.ts` — export new schema.

### 3. API — `apps/api`

**Existing:** `GET /api/devices` — add `?tags=` query param support. Parse comma-separated, filter devices whose tags array contains any matching tag (`arrayOverlaps` or `contains`).

**New file:** `apps/api/src/routes/device-groups.ts`

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| `GET` | `/api/device-groups` | JWT | List groups (search, pagination) |
| `POST` | `/api/device-groups` | Admin/Support | Create group |
| `GET` | `/api/device-groups/:id` | JWT | Group detail with device list |
| `PATCH` | `/api/device-groups/:id` | Admin/Support | Update group |
| `DELETE` | `/api/device-groups/:id` | Admin/Support | Delete group |

`device_count` is maintained on create/update — a simple `arrayLength()` on the `device_ids` column.

**Modified:** `apps/api/src/index.ts` — register group routes.
